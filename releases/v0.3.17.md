# Dot Calendar v0.3.17 — AI 연결, 완료 표시와 선택적 공모전 수집

**AI 연결** 창에서 초기 안내, 오늘부터 7일간의 일정 브리핑, 로컬 MCP 설정 JSON을 각각 선택해 복사할 수 있습니다. 창을 여는 것만으로 클립보드나 외부 AI 설정을 변경하지 않습니다. 브리핑은 오늘의 완료·미완료 항목과 이후 6일의 미완료 항목을 포함하며 메모 본문을 제외합니다. 실제 클라이언트 연결은 선택한 앱에서 확인해야 합니다.

완료 일정은 달력과 하루 목록에 ✓와 읽기 쉬운 구분 색상으로 표시됩니다. 날짜 우클릭의 **새 일정 (시간·반복)…**에서 상세 일정을 만들 수 있고, 로컬 알림의 입력 범위를 저장소와 같은 0–525600분으로 맞췄습니다. 날짜 메뉴는 일정 조작에 집중하고 전역 관리 기능은 ··· 메뉴와 알림 영역에서 제공합니다.

기존 위젯 저장소를 상세 저장과 백업에서 재사용하고, 같은 DPI의 폰트를 중복 생성하지 않도록 했습니다. Google 설정의 없음·손상·읽기 실패를 구분하며, 파일 전체 재읽기·잠금·동시 수정 충돌·저장 후 검증은 유지합니다. 새로운 Rust 의존성은 추가하지 않았습니다.

공개 공모전 수집기는 명시적인 로컬 설정과 기존 PowerShell 7이 있을 때만 켜집니다. KST 기준 매일 첫 실행에 확인하고, 유한한 작업을 마치면 종료합니다. 성공한 출처는 같은 날 다시 조회하지 않습니다. 사용자 수정·완료·삭제 이력·제외 목록을 보존하고, 번호가 바뀐 재게시 공고도 기존 행사와 단계가 겹치면 검토 대기로 남깁니다. 불명확한 참가 자격·날짜·단계는 자동 등록하지 않습니다. DAKER의 robots 접근 제한은 수집 실패로 기록하며 우회하거나 성공 0건으로 처리하지 않습니다. [설정·조회 범위·제약](https://github.com/7065616b/dot-calendar/blob/v0.3.17/integration/contest-collector.md)을 확인하세요.

검증은 Rust 테스트 101개와 선택 기능 제외 빌드 98개, 수집기 회귀 57개, CLI/MCP 저장·동시 추가·복구, AI UI 7개, 사본의 실제 원문 수집과 정상 종료·재시작으로 진행했습니다. 실제 외부 AI 계정 연결과 Google 원격 쓰기는 검증 범위에 포함하지 않았습니다.

동일 Windows 환경에서 1100×730 논리 크기, Google 동기화·수집 비활성, 2초 준비 후 5초 유휴 관측을 각각 3회 수행했습니다. 빈 달력/일반 100개/일별 반복 500개의 전용 메모리 중앙값은 이전 2.63/2.68/5.33MiB, 새 버전 2.62/2.70/5.33MiB였습니다. 두 빌드 모두 해당 유휴 관측 구간의 CPU 증분과 읽기·쓰기 I/O가 0으로 측정됐습니다. 이는 영구적인 0 부하 보장이 아닙니다.

60회 동기 화면 갱신의 최초 비교에서는 반복 500개 CPU 중앙값이 약 11% 증가했으나, 추가 교차 실행 세 쌍의 차이는 0%, −14%, +4%로 변동했습니다. 시작 지연과 그리기 속도의 일관된 개선은 주장하지 않습니다. GDI/User 자원 수는 갱신 전후 각각 17/20으로 유지됐습니다. 실행 파일 크기는 1,291,776 bytes입니다.

Windows 10 1703 이상 / Windows 11 x64 공개 미리보기입니다. 설치 EXE, 휴대용 ZIP과 SHA-256 목록을 제공합니다. 배포 파일에는 개인 일정·계정 정보·수집 결과·활성화 설정·안전 사본을 포함하지 않습니다. 최신 사용자 데이터 위에 과거 백업을 복원하지 마세요.
